# Rollvive 素材生产计划

> 目标：依据项目策划总览，把美术、动画、VFX、UI 与音频需求拆成可生成、可验收、可导入 Cocos Creator 的生产批次。
>
> 当前阶段：先完成前 5 波可玩垂直切片，再扩展完整四角色与长期内容。

## 1. 生产目标

素材生产需要同时满足三个目标：

1. **玩法可读**：玩家在 960×540 横屏和小尺寸战斗单位下，可以快速辨认角色、武器、怪物职责、攻击方向与危险区域。
2. **视觉统一**：所有单位遵循“异星科幻、Hex 能量、装甲织物、晶体生物、2.5D 俯视”的统一设计语言。
3. **可落地**：文件具备透明背景、合理留白、统一朝向和明确命名，能够直接进入 Cocos Sprite、Prefab、动画与对象池流程。

本计划不以“一次性生成最多图片”为目标。生产顺序优先解决视觉风格、前五波核心闭环和实机可读性，再补充高成本立绘、动画与长期内容。

## 2. 当前素材盘点

### 2.1 已有素材

项目当前已有：

- 4 张角色战斗 PNG：`256×256 RGBA`。
- 6 张普通怪物战斗 PNG：`256×256 RGBA`。
- 1 张 Core Brute Boss PNG：`256×256 RGBA`。
- 1 张运行时美术联系表：`1024×768 RGBA`。
- 现有运行时 `Graphics` 绘制角色、武器、攻击和部分反馈效果。

### 2.2 当前判断

现有 PNG 和 `Graphics` 形象均属于几何原型，主要价值是：

- 验证战斗尺寸与碰撞体。
- 验证角色和敌人的基础颜色分组。
- 验证武器方向、怪物职责与同屏密度。
- 作为正式素材导入前的占位与降级方案。

它们不满足最终商业素材标准，主要缺口包括：

- 角色缺少清晰的职业服装、材质层次和武器细节。
- 怪物缺少生物结构、职责轮廓和统一的异星生态语言。
- Boss 缺少阶段变化、技能部件和压迫感。
- 当前没有正式场景、UI 皮肤、Hex 图标、战斗 VFX、动画与音频素材。
- 角色文件仍采用旧稳定 ID 命名，需要保留兼容关系并在制作清单中标明玩家可见名称。

## 3. 统一美术基线

### 3.1 风格关键词

- Stylized 2.5D sci-fi fantasy
- 横屏移动端生存 Roguelite
- 俯视 / 3/4 俯视战斗视角
- 六边形反应堆、骰点符文、能量武器
- 硬质陶瓷装甲、金属边框、织物与晶体混合材质
- 半写实比例，适度夸张头肩、武器和职责部位

### 3.2 禁用方向

- 纯圆点、纯几何块或 emoji 风格。
- 过度 Q 版、幼儿化或只有大头的比例。
- 写实照片、3D 渲染截图或复杂背景合成。
- 纯中世纪服装和普通冷兵器造型。
- 武器过小，无法在战斗尺寸中辨认。
- 大量烟雾、透明光污染和不可控的软边。
- 把文字、边框、阴影地面直接烘焙进战斗 Sprite。

### 3.3 色彩规则

| 内容 | 主色方向 | 目的 |
| --- | --- | --- |
| 玩家角色 | 蓝、青、紫、金属白，辅以职业强调色 | 与敌人建立阵营区分 |
| 普通敌人 | 红、橙、酸绿、暗紫 | 快速识别敌对目标 |
| 玩家攻击 | 青蓝、金白、紫蓝 | 与角色职业对应 |
| 敌方攻击 | 红橙、洋红、酸绿 | 与玩家攻击明显区分 |
| 危险预警 | 红橙边缘＋低透明填充 | 保证第一时间可见 |
| Hex 稀有度 | 蓝、紫、金 | 建立稳定的奖励层级 |

### 3.4 战斗尺寸

| 类型 | 运行时目标高度 | 建议源文件 |
| --- | ---: | ---: |
| 玩家 | 42～64 px | 512×512，至少 256×256 |
| 普通怪 | 30～48 px | 256×256 |
| 精英怪 | 46～64 px | 384×384 或 512×512 |
| Boss | 100～140 px | 768×768 或 1024×1024 |
| UI 头像 | 96～160 px 显示 | 512×512 源文件 |
| 角色选择立绘 | 约 420～520 px 高显示 | 768×1024 或 1024×1024 |

所有核心单位必须在 64、96、128 px 三种预览尺寸下进行辨识测试。

## 5. A0：风格锁定批次

### 5.1 目标

用最少素材验证整个游戏的视觉方向。未通过此阶段，不批量生成其余角色和怪物，避免出现大量风格不一致的返工。

### 5.2 首批样张

| 编号 | 素材 | 选择理由 | 数量 |
| --- | --- | --- | ---: |
| A0-01 | 短刃决斗家战斗 Sprite | 验证玩家比例、双武器和近战轮廓 | 3 个候选 |
| A0-02 | Void Chaser 战斗 Sprite | 验证基础追击怪和小尺寸敌人 | 3 个候选 |
| A0-03 | Core Tank 战斗 Sprite | 验证厚重材质和空间压缩职责 | 3 个候选 |
| A0-04 | Rift Dasher 战斗 Sprite | 验证高速尖锐轮廓和预警方向 | 3 个候选 |
| A0-05 | Core Brute Boss 概念图 | 验证 Boss 体量、晶核和章节主题 | 3 个候选 |

每类先生成 3 个方向候选，只选择 1 个继续精修。候选之间可以改变轮廓和装备结构，但必须保持统一视角、光照和材质语言。

### 5.3 风格锁定评审点

- 角色与怪物是否属于同一世界。
- 角色武器在 64 px 高度下是否仍然可见。
- Chaser、Tank、Dasher 是否可以只看轮廓判断职责。
- Boss 是否明显区别于普通怪放大版。
- 玩家与敌人的主色是否清楚分离。
- 输出是否便于抠图，边缘是否干净。

### 6.2 基础战场

前五波只生产一套可重复使用的“坠毁区”战场：

- `bg_crash_site_base`：无缝或大尺寸基础地表，建议 1920×1080。

战场需要控制对比度，不能与角色、敌人、弹道和红色预警争抢视觉注意力。

首张“坠毁区”基础地图已完成生成与静态可读性检查，详见 [CrashSiteMapReview.md](CrashSiteMapReview.md)。运行时接入尚未执行。

### 6.3 核心 UI

- 玩家生命条底板、填充与受伤状态。
- Boss 血条底板、填充与阶段标记。
- 波次标题牌和 Boss 警告条。
- 虚拟摇杆底盘与摇杆头。
- 1 个主动技能按钮底板。

UI 首轮优先制作九宫格可缩放底板和独立图标，避免把文字烘焙进图片。

### 7.2 每名角色交付

- 角色选择立绘：1 张，`768×1024` 或 `1024×1024`。
- UI 头像：1 张，`512×512`。
- 战斗待机图：1 张，`512×512` 透明 PNG。
- 移动关键帧：2～4 张。
- 攻击关键帧：3～6 张。

- 短刃：弧形刀光、多刀扇面、近身回旋。

- 双枪：左右枪口火焰、细弹道、穿透火花与暴击反馈。
- 范围魔法：小型符文圈、区域脉冲、短链和延迟爆发。

角色 VFX 必须保留透明空隙，不做持续覆盖单位的大面积常亮效果。

## 8. A3：完整敌人与 Boss 资产

### 8.1 第一章节普通怪

完整生产以下 6 类：

1. Void Chaser：尖锐前倾的基础追击轮廓。
2. Core Tank：厚壳、宽体、低重心。
3. Hex Swarm：小型成群飞行寄生体。
4. Rift Dasher：三角翼片与明显冲刺方向。
5. Star Spitter：喉囊、炮口或背部弹道器官。
6. Gravity Binder：悬浮重力环与中心控制核心。

每类至少交付：待机、受击、死亡和职责相关技能素材。精英变体优先通过轮廓附件、晶核、材质裂纹和配色实现，不能只做简单放大或整体染色。

### 8.2 Core Brute Boss

Boss 需要：

- 1 张选择/登场概念图。
- Phase 1 战斗 Sprite。
- Phase 2 破裂变体。
- 普通攻击关键帧。
- 冲锋蓄力与冲刺关键帧。
- 能量炮或范围技能关键帧。
- 胸口晶核破裂和死亡素材。
- Boss 头像或血条图标。
- 每个技能对应的预警图形。

Phase 2 必须通过晶核裂纹、装甲脱落、能量颜色或武器结构产生明显变化。

## 9. A4：UI、图标、动画与音频完善

### 9.1 Hex 图标

图标使用六边形底形，按照五个家族建立稳定符号：

- 武器：刀刃、弹丸、分裂、连锁、环绕。
- 属性：心脏、盾牌、攻击、攻速、范围。
- 机动：足迹、闪避、推进器、护盾窗口。
- 功能：刷新箭头、额外卡位、幸运骰点、稀有度星标。
- 风险：裂纹核心、破碎心脏、双刃天平、警告符号。

第一批只为当前代码中已经存在并可抽取的 Hex 生成图标，避免图标先于机制大量堆积。

### 9.2 音频清单

#### 武器 SFX

- 短刃挥砍、命中、强化多刀。
- 霰弹枪开火、机械上膛、重击命中。
- 双枪左右开火、穿透、暴击。
- 魔法蓄能、范围爆发、连锁跳转。

#### 战斗 SFX

- 玩家受击、护盾、濒死和死亡。
- 普通怪受击与死亡。
- 精英出现、Boss 登场、Boss 破防与死亡。
- 波次开始、清波和结果结算。

#### UI SFX

- 按钮点击、确认、返回。
- Hex 翻牌、选择、蓝/紫/金稀有反馈。
- 免费刷新、广告刷新和不可用提示。

#### BGM

- 标题/角色选择：1 首。
- 坠毁区普通战斗：1 首，可分层增强。
- Boss 战：1 首。
- 结算：胜利与失败短乐段各 1 个。

### 9.3 音频技术建议

- BGM 使用可循环 OGG 或平台推荐格式。
- 高频短音效使用 WAV 源文件，导入后按平台压缩。
- 同类命中音提供 2～4 个轻微变化，避免机械重复。
- 对高攻速武器和群体命中设置并发与触发间隔限制。

## 11. 单项生成工作流

每个核心单位按以下流程执行：

1. 从策划确认战斗职责、攻击方式和玩家应对。
2. 编写正向提示词、负向提示词和固定风格前缀。
3. 生成 3 个低成本方向候选。
4. 选择一个轮廓继续精修，不在多个方向之间反复拼接。
5. 输出高分辨率主图和透明背景版本。
6. 清理边缘、残留背景、错误肢体和武器结构。
7. 生成受击、攻击或 Phase 2 变体。
8. 制作 64/96/128 px 联系表进行可读性评审。
9. 导入 Cocos，绑定 SpriteFrame、Prefab 与运行时尺寸。
10. 在 960×540 真正战斗场景中测试，而不是只看单张大图。
11. 记录提示词、候选图、接受/拒绝原因和导入结果。

## 12. 生成提示词结构

统一提示词至少包含：

```text
Use case: stylized game asset
Asset type: [角色/怪物/Boss/UI/VFX] battle asset
Subject: [职责、武器、身体结构、核心记忆点]
Style: polished 2.5D sci-fi fantasy online mobile game art
Camera: top-down / 3/4 top battle view
Composition: centered, full body, generous transparent padding
Materials: layered armor, fabric, alien crystal, hex-tech energy
Readability: strong silhouette, readable at 64 px combat height
Palette: [主色、辅色、发光色]
Constraints: transparent background, no text, no watermark, no UI frame
Avoid: geometric placeholder, chibi-only, photorealism, noisy micro-details,
soft smoky edges, baked shadow, cropped weapon, extra limbs
```

详细角色与怪物提示词继续以 [VisualAssetProductionSpec.md](VisualAssetProductionSpec.md) 为基础；正式生产前需要将其中旧角色称呼统一映射到当前四角色阵容。

## 13. 质量验收清单

### 13.1 视觉

- 不看文字即可识别角色职业或怪物职责。
- 角色绑定武器清楚可见，没有裁切或结构错误。
- 正确采用 3/4 俯视视角，脚部和顶部比例一致。
- 轮廓在 64 px 高度下仍然成立。

- 原始候选与最终选择。

- `_concept_v01`：概念候选。
