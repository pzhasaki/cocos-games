# Rollvive 游戏设计总纲

> 目标：把当前可跑通的粗糙流程，逐步打磨成一个适合移动端 / 抖音小游戏场景的精致生存 Roguelite。
> 这份文档负责“游戏应该是什么、先做什么、怎么验收”；代码结构细节放在 `GameArchitecture.md`。
> 前 5 波、首批角色和 Hex 家族的数据切片见 `ContentPlan.md`。
> 长期角色、剑 / 枪等武器、怪物、波次节奏和性能预算归档见 `CharacterWeaponMonsterDesign.md`。

## 1. 当前判断

现在不应该直接从“大量角色和怪物类型”开始堆内容。

更合理的顺序是：

1. 先锁定 30 秒核心乐趣：移动、躲避、自动攻击、受压、清怪、奖励选择。
2. 再定义角色和怪物类型：角色负责流派入口，怪物负责战斗压力。
3. 然后做波次节奏和 Hex 强化：让每一波都产生不同决策。
4. 最后精修表现、音效、特效、手感和性能。

原因很直接：角色和怪物不是独立好玩的，它们必须服务于“玩家怎么移动、怎么打、怎么被逼迫、怎么成长”。如果核心战斗手感没定，先设计几十个角色和怪物会很快变成无效内容。

## 2. 产品定位

Rollvive 是一款竖屏移动端生存 Roguelite。

核心体验：

- 左手摇杆移动，右手少量主动按钮。
- 武器自动攻击最近或最有威胁的敌人。
- 每波战斗结束后，从随机 Hex 强化中选择 1 个成长方向。
- 不做金币经济；每次 Draft 给 1 次免费刷新，继续刷新走激励广告口子。
- 单局短节奏，前 30 秒必须能看懂，前 3 分钟必须形成构筑感。

关键词：

- 易上手
- 高压躲避
- 自动攻击
- 随机成长
- 小屏幕可读
- 性能稳定

## 3. 优先级路线

### P0：可玩核心

目标：从 START 进入后，不再只是占位画面，而是能形成完整的小循环。

必须完成：

- 摇杆移动手感稳定。
- 敌人会追击、包围、造成接触伤害。
- 玩家自动攻击，命中反馈清楚。
- 血量、波次、敌人数量、技能状态可读。
- 清波后进入 Hex Draft。
- 选择强化后能明显改变下一波体验。
- 死亡后进入结算。

验收标准：

- 不看代码，只用鼠标拖摇杆或 WASD，就能玩完至少 3 波。
- 玩家能说出“我刚才选的强化让什么变强了”。
- 屏幕上任何时候都能看懂：我是谁、敌人在哪、血量多少、下一步点哪里。

### P1：角色与怪物骨架

目标：不是一次性做很多内容，而是先把“类型体系”搭好。

先做 3 个角色原型：

| 角色 | 定位 | 核心乐趣 | 风险 |
| --- | --- | --- | --- |
| Blade Adept | 新手稳定型 | 多刀、均衡、容易理解 | 后期上限普通 |
| Hex Gambler | 随机高收益型 | 更好的稀有强化和刷新体验 | 血少、容错低 |
| Storm Mage | 连锁清场型 | 链式攻击、范围成长 | 前期弱、怕贴脸 |

先做 5 类怪物原型：

| 怪物 | 战斗职责 | 玩家应对 |
| --- | --- | --- |
| Chaser | 基础追击怪 | 保持移动，不被围住 |
| Tank | 慢速高血怪 | 拉扯，依靠成长输出 |
| Dasher | 冲刺怪 | 观察预警，横向躲避 |
| Spitter | 远程怪 | 优先靠近或利用走位规避 |
| Elite/Boss | 波次压力核心 | 读机制，控制距离 |

注意：每个怪物必须有明确职责。不要只做“血更多、速度更快”的重复怪。

### P2：构筑深度

目标：每次 Draft 的选择都能改变打法。

Hex 强化分 5 个家族：

| 家族 | 功能 |
| --- | --- |
| Blade | 改变攻击数量、角度、连锁、环绕 |
| Stat | 血量、护甲、伤害、攻速、范围 |
| Mobility | 移速、闪避、冲刺、防御窗口 |
| Risk | 高伤害但降血、降防或增加危险 |
| Utility | 免费刷新次数、选择数量、稀有度倾向 |

当前明确规则：

- 不做金币。
- 每次 Draft 默认 1 次免费刷新。
- 免费刷新用完后，按钮变成激励广告入口。
- 本地预览先模拟广告成功，后续由平台适配层接入真实 SDK。

### P3：精致化

目标：从“能玩”变成“愿意多玩一局”。

重点不是大幅加内容，而是打磨反馈：

- 攻击轨迹要可见。
- 受击要有短促反馈，但不能遮挡视线。
- 怪物死亡要有轻量爆裂或消散。
- Boss 出场要有警示和血条。
- Draft 卡牌要能一眼看出稀有度、流派和风险。
- 摇杆、按钮、HUD 要稳定，不随文字和状态跳动。
- 音效要给攻击、受击、选择、刷新、死亡提供即时反馈。

## 4. 核心战斗设计

### 输入

正式移动端输入：

- 左下角虚拟摇杆控制移动。
- 右下角保留 1 到 2 个主动按钮。
- 武器自动攻击，不要求玩家频繁点攻击键。

本地预览输入：

- 鼠标拖动摇杆模拟触摸。
- WASD / 方向键作为调试快捷输入。

### 战斗节奏

一波战斗应包含：

1. 进场提示。
2. 少量基础怪建立移动压力。
3. 中段加入特殊怪打破单调。
4. 末段提高密度或出现精英。
5. 清波后短暂停顿，进入 Draft。

单波时长建议：

- 前 3 波：20 到 35 秒。
- 中期普通波：35 到 55 秒。
- Boss 波：60 到 90 秒。

### 自动攻击

基础规则：

- 默认攻击最近敌人。
- 如果存在精英 / Boss，可提高目标优先级。
- 攻击范围、冷却、刀数量、连锁、分裂由角色和 Hex 共同决定。

需要避免：

- 攻击特效太大导致看不清敌人。
- 子弹 / 刀光数量无限增长。
- 每帧频繁创建节点。

## 5. 角色设计原则

角色不是皮肤，而是开局规则。首批版本中，角色应当绑定初始武器，形成一个清晰的开局套装；计算层仍使用统一攻击参数模型，避免每个角色各写一套战斗逻辑。

每个角色必须定义：

- 起始血量和防御容错。
- 起始攻击方式。
- 绑定的初始武器和可扩展副武器方向。
- 擅长的 Hex 家族。
- 明显弱点。
- 适合的新手程度。

表现层不应长期使用圆点作为角色。圆点 / Graphics 只用于原型期验证移动、碰撞和攻击范围；正式路线应逐步替换为 Sprite / Prefab / 关键角色动画，并保证这些资产可池化、可降级、不会破坏移动端性能预算。

第一批只做 3 个角色，先保证差异真实可感：

### Blade Adept

定位：默认推荐角色。

特点：

- 初始双刀。
- 血量和护甲较稳定。
- 适合学习走位和 Draft。

### Hex Gambler

定位：随机成长型。

特点：

- 初始血量低。
- 稀有强化概率更好。
- 每次 Draft 的刷新体验更强。

### Storm Mage

定位：连锁清场型。

特点：

- 攻击范围更远。
- 连锁成长收益更高。
- 前期怕贴脸，依赖走位。

## 6. 怪物设计原则

怪物类型应该按“战斗职责”设计，而不是按外观设计。

基础组合：

| 类型 | 速度 | 血量 | 伤害 | 行为 |
| --- | --- | --- | --- | --- |
| Chaser | 中 | 低 | 低 | 持续追玩家 |
| Tank | 慢 | 高 | 中 | 压缩空间 |
| Dasher | 快 | 中 | 高 | 蓄力后冲刺 |
| Spitter | 慢 | 低 | 中 | 远程吐弹 |
| Swarm | 快 | 很低 | 低 | 数量多，制造拥挤 |

组合原则：

- 第 1 波只出现 Chaser。
- 第 2 到 3 波加入 Tank 或 Swarm。
- 第 4 波开始加入 Dasher 或 Spitter。
- 第 5 波出现第一个 Boss。
- 每个新怪第一次出现时，数量要少，让玩家读懂机制。

## 7. 波次设计

前 5 波建议：

| 波次 | 目标 | 怪物组合 | 重点 |
| --- | --- | --- | --- |
| 1 | 学移动和自动攻击 | Chaser | 低压教学 |
| 2 | 学拉扯 | Chaser + Tank | 不被围住 |
| 3 | 学构筑反馈 | Chaser + Swarm | 感受强化 |
| 4 | 学特殊威胁 | Chaser + Dasher | 读预警 |
| 5 | 第一个小 Boss | Boss + 少量 Chaser | 阶段验收 |

后续波次通过参数表扩展：

- 敌人数量
- 刷怪间隔
- 精英概率
- 特殊怪权重
- Boss 血量和机制

## 8. UI 与信息层级

战斗中最重要的信息：

1. 玩家位置和血量。
2. 敌人位置和威胁。
3. 攻击 / 技能反馈。
4. 波次进度。
5. 当前关键属性变化。

Draft 中最重要的信息：

1. 三到四个可选强化。
2. 稀有度。
3. 强化属于哪个家族。
4. 会带来什么收益和代价。
5. 免费刷新剩余次数或广告刷新入口。

禁止：

- 大段说明文字压住游戏画面。
- 卡牌描述过长导致小屏读不完。
- 按钮文案变化导致布局跳动。

## 9. 性能设计

性能是设计约束，不是最后优化。

移动端预算：

- 目标 60 FPS，低端机可降级到 30 FPS。
- 同屏敌人先控制在 36 以内。
- 弹道、伤害数字、VFX 都必须使用对象池。
- HUD 刷新节流到 10Hz 左右。
- AI 决策不必每帧执行。
- 每波结束必须回收敌人、弹道、特效、临时节点。

后续新增任何怪物、武器、特效，都必须回答：

- 最坏情况下同屏会有多少个？
- 是否复用对象池？
- 是否会每帧分配数组或字符串？
- 是否会遮挡核心信息？

## 10. 版本推进建议

### Milestone 1：战斗变得可玩

- 抽出 `VirtualJoystick`。
- 抽出 `BattleRuntime` / `BattleSystem`。
- 做敌人 HP 条和死亡反馈。
- 做攻击轨迹和命中反馈。
- 做前 5 波参数。

### Milestone 2：内容骨架

- 接入 3 个角色选择。
- 接入 5 类怪物行为。
- 接入 Boss 1。
- Hex Draft 卡牌按家族重新整理。

### Milestone 3：产品质感

- 替换临时图形为正式 Sprite / Prefab。
- 加音效。
- 加屏幕震动和轻量特效。
- 加结算统计。
- 加性能监控开关。

### Milestone 4：平台化

- 接入抖音 / TikTok 平台适配。
- 激励广告刷新接真 SDK。
- 做存档和基础设置。
- 做首屏加载和异常兜底。

## 11. 当前下一步

建议下一步不要继续只改 UI 占位，而是做一个完整的 Milestone 1 切片：

1. 保留当前能打开的 `RuntimeEntry` 作为稳定入口。
2. 把摇杆、战斗循环、敌人、攻击、波次拆成可维护模块。
3. 补齐 Chaser / Tank / Dasher 三种敌人。
4. 补齐清晰的攻击轨迹、敌人血条、死亡反馈。
5. 让前 5 波能完整玩下来。
6. 每波结束都能看到 Hex 选择和 1 次免费刷新。

完成这个切片后，再进入角色选择和更复杂的怪物 / Boss 设计。

## 12. 可执行设计规范摘要

本节把角色、武器、怪物、表现和性能约束压缩成实现者可直接执行的产品规则。详细字段见 `CharacterWeaponMonsterDesign.md`，模块拆分见 `GameArchitecture.md`。

### 12.1 角色与武器绑定

首批内容不做“角色和武器完全自由搭配”。玩家选择角色时，同时选择一套可理解的开局打法。

必须遵守：

- `Blade Adept -> 剑`，新手稳定、多刀、近中距离。
- `Hex Gambler -> 枪`，远距离穿透、高收益但低容错。
- `Storm Mage -> 法球`，中远距离连锁、前期怕贴脸。
- 副武器只通过 Hex、局外解锁或调试配置进入，不作为首屏基础选择。
- 角色只提供初始参数、成长权重、Draft 倾向和表现身份，不拥有独立战斗主循环。

### 12.2 武器攻击参数统一

所有攻击最终进入统一 `AttackProfile`，由同一个攻击解析流程执行。最低字段包括 `shape`、`targetPolicy`、`range`、`hitRadius`、`cooldownMs`、`damage`、`projectileSpeed`、`pierce`、`chainCount`、`orbitCount`、`vfxBudgetCost`、`poolKey`。

设计红线：

- 不为某个角色硬写专属攻击算法。
- 不让 Hex 直接操作节点或特效。
- 不允许弹道、连锁、环绕、分裂无上限叠加。
- 不允许表现特效优先级高于可读性。

### 12.3 角色表现迁移路线

Graphics 圆点只是原型验证手段，不是正式表现目标。正式路线按以下顺序迁移：

1. 角色：Sprite / Prefab 先替换玩家身份，至少有待机、移动、受击表现。
2. 武器：攻击轨迹与 `shape` 对齐，保证剑、枪、法球、环刃一眼不同。
3. 怪物：按职责区分轮廓、颜色、预警，不靠数值说明。
4. VFX：命中、死亡、连锁、Boss 预警进入对象池，并声明预算。
5. 降级：低端模式保留核心轮廓和预警，减少残影、粒子、长生命周期特效。

### 12.4 怪物扩展原则

怪物新增必须先定义职责，再定义数值和外观。

| 类型 | 职责 | 玩家动作 |
| --- | --- | --- |
| Chaser | 基础追击 | 保持移动。 |
| Tank | 压缩空间 | 拉扯、绕开、等待输出成长。 |
| Swarm | 数量拥挤 | 用范围和走位清理。 |
| Dasher | 爆发冲刺 | 读预警，横向闪避。 |
| Spitter | 远程压制 | 换位，优先击杀或绕弹道。 |
| Binder | 限制区域 | 避开控制区，打断舒适路线。 |

新增怪物前必须写明首次出现波次、教学数量上限、同屏最大数量、是否产生弹道 / 预警 / 召唤物 / 控制区，以及与现有怪物组合时制造什么新压力。

### 12.5 性能预算红线

- 目标 60 FPS，低端模式允许降到 30 FPS。
- 活跃敌人默认上限 36。
- 活跃弹道默认上限 80。
- 活跃 VFX 默认上限 24。
- 活跃伤害数字默认上限 18。
- HUD 普通刷新节流到 10Hz。
- AI 决策默认 100ms 一次。
- 怪物、弹道、伤害数字、短生命周期 VFX、hitbox 必须对象池化。

任何新内容如果无法说明“最坏同屏数量、对象池键、超预算降级策略”，不进入实现排期。

## 13. 设计到实现里程碑

### Milestone A：规则定型

- 固定 3 个角色与初始武器绑定。
- 固定 4 个武器 `AttackProfile` 模板。
- 固定 6 类基础怪物职责。
- 固定性能预算常量和对象池统计口径。

### Milestone B：模块落地

- 角色选择只写入 `characterId`，由配置解析出初始武器。
- 攻击系统只消费 `ResolvedAttackProfile`。
- Wave 配置只引用 `monsterId` 和权重，不在流程里硬编码怪物行为。
- VFX、弹道、伤害数字改为对象池申请和回收。

### Milestone C：表现替换

- 玩家从 Graphics 迁移到 Sprite / Prefab。
- 剑、枪、法球、环刃拥有可区分攻击轨迹。
- Chaser、Tank、Swarm、Dasher、Spitter、Binder 拥有可读轮廓。
- Boss 和精英拥有预警、血条和差异化描边。

### Milestone D：预算回归

- 压测同屏 36 敌人、80 弹道、24 VFX。
- 记录对象池命中率和临时实例化次数。
- 验证低端模式降级后核心信息仍可读。
- 平台接入前完成一次完整 10 波回归。
